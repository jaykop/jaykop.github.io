# Devlog Check

기계적 항목은 스크립트가, 판단이 필요한 항목만 사람이 본다. 252편을 한 번에 돌려도 몇 초면 끝난다.

## 실행 시점

- 글을 새로 쓰거나 크게 고친 직후
- 커밋 전
- 카테고리·경로를 옮긴 뒤 (링크가 조용히 깨지는 자리다)

## Step 1 — 자동 검사

```bash
python .claude/skills/devlog-check/devlog_check.py _posts/unreal/combat/2025-08-12-SoftTarget.md
python .claude/skills/devlog-check/devlog_check.py --all
```

**내부 링크 검사는 `_site/` 가 있어야 돈다.** 없으면 그 항목만 건너뛴다. 정확히 보려면 먼저 빌드한다:

```bash
bundle exec jekyll build
```

`[문제]` 가 하나라도 있으면 exit 1. 스크립트 출력을 결과에 그대로 옮긴다.

### 확정 문제로 잡는 것

| 항목 | 내용 |
|---|---|
| front matter | 없거나 `title` · `categories` 누락 |
| 제목 접두사 | `[C++]` `[DevNote]` 처럼 대괄호 접두사가 있는지, 아는 접두사인지 |
| 카테고리 | 정확히 2단계인지 (대분류 + 소분류) |
| 코드블록 언어 태그 | `c` `cs` `c#` `cpp` `js` 같은 별칭 — `c++` `csharp` `javascript` 로 통일 |
| 코드블록 탭 | 탭은 `<pre>` 에서 8칸으로 벌어진다. 2칸 공백으로 |
| 이미지 경로 | 파일이 실제로 있는지, `assets/images/<글-slug>/` 안에 있는지 |
| 내부 링크 | `jaykop.github.io/...` 가 실제 페이지를 가리키는지 |
| 앵커 | `](#앵커)` 가 실제 제목과 맞는지 |
| 표기 갈림 | 한 글 안에서 셰이더/쉐이더, 대미지/데미지처럼 갈리는 것 |
| 금지어 | 영어 관용구를 낱말째 옮긴 표현 |
| BOM | BOM 없는 UTF-8 이어야 한다 |
| `_posts` 안 확장자 없는 파일 | Jekyll 이 글로 인식하지 않는다. 미완성이면 `_drafts/` 로 |

### 참고로만 보고하는 것

언어 태그 없는 코드블록, 4칸 들여쓰기, 다른 글 폴더의 이미지를 참조하는 경우, 주어에 따라 갈리는 낱말.

## Step 2 — 판단 검사

스크립트가 못 잡는 것만 본다. 새로 쓴 부분 위주로, 전체 재검토가 아니다.

### 2-1. 직역투

쓰려는 표현을 영어로 옮겨봐서 원래 관용구가 튀어나오면 직역이다. 고치는 법은 비유를 버리고 그 비유가 가리킨 사실을 쓰는 것이다.

| 쓰지 말 것 | 대신 |
|---|---|
| 여기가 구멍이다 | 이 경우를 처리하지 않는다 |
| 냄새가 난다 | 나중에 문제가 될 것 같다 |
| 폴백 | 대체 (에디터 필드명 `Fallback` 은 그대로) |
| 죽은 코드 | 안 쓰이는 코드 |
| 이 경로는 살아있다 | 이 경로는 동작 중이다 |

새로 찾은 직역투는 `devlog_check.py` 의 `BANNED` 에 추가한다. 다음부터는 스크립트가 잡는다.

### 2-2. 언리얼 용어 표기

번역어와 원어가 한 글 안에서 섞이지 않게 한다. 코드·에디터에 그대로 나오는 이름(`UPROPERTY`, `Fallback`, `Behavior Tree`)은 원문 그대로 두고, 설명하는 말만 한국어로 쓴다. 새 표기 갈림을 찾으면 `VARIANT_SETS` 에 추가한다.

### 2-3. DevNote 인지 확인

`[DevNote]` 는 **실제로 작업한 프로젝트에서 겪은 일**에만 붙인다. 엔진 문서를 읽고 정리한 글이면 `[Unreal]` 이다. 이 구분이 이 사이트에서 실무 경험을 가리키는 유일한 표시라, 섞이면 표시가 아무 뜻도 갖지 못한다.

## Step 3 — 결과 보고

문제를 파일·줄 번호와 함께 나열하고, 고칠지 묻는다. 자동으로 고치지 않는다 — 특히 문장은 글쓴이 목소리다.
